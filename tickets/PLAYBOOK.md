# 티켓 처리 노하우 (사용자가 알려준 규칙 모음 - 읽기/다시 정리 때마다 Claude가 따른다)

새 규칙은 아래에 한 줄씩 추가한다(날짜 + 규칙 + 이유). 기본 규칙(CHECK_PROMPT.md)보다 이쪽이 우선.

- 2026-10-16 **S/N이 있고 이동·처리 요청(배송/회수/픽업/수출/수입 등)이면 사용자가 말하지 않아도** S/N 하나당 한 줄로 정리한다. `sn`은 줄바꿈 구분, `mn`은 같은 순서로 매칭(모르면 빈 줄로 줄 수 맞춤). 반영하면 보드에 S/N 한 개당 한 행이 생긴다(한 칸에 쉼표/줄바꿈으로 몰아넣지 않는다). 이유: 사용자가 "한 줄씩"을 반복해서 요청.
- 2026-10-16 서울 창고팀(나)이 서울오피스 **반납함/리턴함에서 픽업**하라는 요청 = Type `회수`, Order# `SDSK 숫자`, 받는 곳은 요청자/장소, 주소는 서울오피스 리턴함. (예: SDSK 1339879599 HDD 8개 폐기)
- 2026-10-16 SAP 오더번호가 없는 사내 배송/회수는 `new_row`(Order#=`SDSK 숫자`). 날짜가 티켓에 없으면 비워 둔다(사용자가 입력).
- 2026-10-16 사용자는 읽기 전에는 티켓 종류를 모른다. 분류는 Claude가 처음부터 끝까지 해서 카드에 올리고, 틀리면 카드의 `다시 정리`로 한 줄 지시를 받는다.
- 2026-10-16 **수출/수입 건은 Type을 `Bloomberg`로** 한다(보드 Type 목록: 배송/회수/Bloomberg/Delayed/회수 Delayed).
- 2026-10-16 **날짜가 티켓에 없으면** `new_row.date`를 비우지 말고 **오늘(티켓을 읽은/수집한 날)**로 채운다.
- 2026-10-16 **기존 행 먼저 찾기(필수)**: 티켓 본문의 관련 번호(ZRX/ZRE/ZOR 등 SAP 오더, OBD, ORD, SDSK)와 **S/N을 모두** `board <번호 또는 S/N>`으로 검색한다. 번호마다, S/N은 몇 개 대표로 검색한다.
  - 기존 행이 있으면: 티켓 내용과 행(Memo, S/N, 날짜, Type)을 비교해서 → 이미 같은 내용이면 `none`(TO DO에 "이미 반영됨"), 메모만 부족하면 `append_memo`(빠진 내용만, 중복 줄 제외), 행에 없는 S/N·날짜 변경 등 더 필요한 게 있으면 `append_memo`로 그 내용을 적고 `question`/TO DO에 "추가로 필요: …"를 명시한다.
  - 번호·S/N으로 검색해도 없을 때만 `new_row`를 제안한다. (`SDSK 숫자`로 이미 만든 행도 검색에 걸린다.)
